# 唐末五代战略游戏 — 设计规格

## 概述

以唐末五代（约公元 880-960 年）为背景的大地图争霸型策略游戏。玩家选择或自建势力，经营内政、外交用间、调兵遣将，最终统一天下。采用网页技术开发（Phaser.js 渲染），先支持人机对战，架构预留联网扩展。

---

## 1. 技术栈

| 层 | 技术 | 职责 |
|---|---|---|
| 画面层 | Phaser 3 + Phaser Isometric Plugin | 2.5D 地图渲染、场景切换、点击交互、战斗画面 |
| 逻辑层 | 纯 JavaScript（独立于 Phaser） | 游戏规则、回合结算、战斗计算、AI 决策 |
| 数据层 | JSON 静态文件 | 城池坐标与属性、武将数据、势力初始配置 |
| 存档 | 第一版：浏览器 localStorage；后续版：服务端云存档 | 游戏进度持久化 |
| 打包 | Capacitor（后续） | 将网页打包为 iOS/Android App |

逻辑层与画面层严格分离：逻辑层不引用任何 Phaser 模块，所有游戏状态由逻辑层产出，画面层只负责将状态绘制出来。这是未来将逻辑搬到服务器端实现联网对战的前提。

---

## 2. 整体架构

```
玩家输入 → Phaser 画面层 → 调用逻辑层 API → 逻辑层计算新状态
                                              ↓
                                         JSON 数据（地图、武将）
```

- 画面层是「显示屏」：响应点击和拖拽，将数据画成图和动画
- 逻辑层是「规则本」：不关心画面，只关心数字和规则

---

## 3. 地图系统

### 3.1 地图规模

- 约 15-20 个州级区域（河北、河东、河南、关中、淮南、江南、剑南、岭南等）
- 每个州下辖 3-8 座城池，总计约 80-100 座城
- 地图采用菱形瓦片（等距/2.5D 视角），有山川河流等地形

### 3.2 城池属性

每座城拥有以下数值：
- 人口：决定征兵上限和税收基数
- 农业：影响人口增长速度
- 商业：影响每回合金钱收入
- 城防：影响攻城难度和防守方伤亡
- 民心：影响征兵意愿和间谍破坏成功率，过低会暴动
- 驻军：当前驻扎的部队数量
- 太守：派驻的武将（管理型武将影响经营效率，军事型武将影响城防）

### 3.3 初始势力（约 880 年格局）

| 势力 | 主城 | 特点 |
|---|---|---|
| 李克用（河东） | 太原 | 骑兵强，武将精锐 |
| 朱温（宣武） | 汴州 | 兵力雄厚，扩张快 |
| 李茂贞（凤翔） | 凤翔 | 地处险要，易守难攻 |
| 杨行密（淮南） | 扬州 | 商业富庶，钱粮充足 |
| 王建（西川） | 成都 | 偏安一隅，潜力大 |
| 钱镠（镇海） | 杭州 | 水军优势（后续版本） |
| 小势力若干 | 各占 1-2 城 | 初期可吞并目标 |

## 4. 时间系统

采用混合制：
- **经营阶段（回合制）**：玩家操作内政、外交、间谍、调兵，完成后点「结束回合」，时间推进一个月，AI 势力同步行动
- **战斗阶段（实时制）**：当两军交战时，切换到战场场景，实时操控部队

---

## 5. 经营系统

### 5.1 内政

每回合可执行以下操作（消耗金钱和行动力，或由太守属性影响效率）：

每回合行动力 = 势力总城池数 × 2（即城越多能做的事越多）。每项操作消耗 1 点行动力。AI 势力同样受行动力限制。金钱是另一项独立消耗。

| 操作 | 效果 | 条件 |
|---|---|---|
| 开发农田 | 农业值+1 | 金钱 + 太守政治属性 |
| 开发市场 | 商业值+1 | 金钱 + 太守政治属性 |
| 修筑城墙 | 城防值+1 | 金钱 |
| 征兵 | 人口-若干，增加部队 | 该城人口≥征兵数 |
| 训练 | 提升部队士气/经验 | 时间（多回合） |
| 流任/召回武将 | 任命或更换太守 | 武将在该城 |

每回合结算：收入 = Σ(各城商业值 × 税率)，人口增长 = Σ(各城农业值 × 基础增长率)，部队消耗 = Σ(各部队维护费)。

### 5.2 武将系统

- 武将属性：统率（带兵上限和战斗加成）、武力（单挑和士气影响）、智力（间谍和计谋）、政治（经营效率）、魅力（忠诚和其他武将关系）
- 忠诚度：可被敌方间谍离间，忠诚低于阈值可能叛变
- 每个武将可带一支部队，部队规模受统率值限制

### 5.3 兵种

第一期三种基础兵种：
- 步兵：攻防均衡，造价便宜，克制弓兵
- 骑兵：移动快、冲锋强，造价贵，被步兵克制
- 弓兵：远程攻击，身板脆，克制骑兵

兵种克制关系：步兵 > 骑兵 > 弓兵 > 步兵（环形克制）

## 6. 外交系统

| 外交行为 | 效果 | 条件/代价 |
|---|---|---|
| 结盟 | 双方约定互不侵犯，可联合作战 | 需对方同意，关系值影响成功率 |
| 通商 | 双方每回合额外获得金钱 | 需结盟状态 |
| 联姻 | 大幅提升关系，长期稳定 | 需有适龄武将亲属 |
| 宣战 | 进入战争状态 | 降低声望 |
| 撕毁盟约 | 单方面取消同盟 | 大幅降低声望，其他势力信任下降 |
| 停战求和 | 结束战争 | 可能需赔款或割城 |
| 劝降 | 说服对方整个势力归顺 | 你实力远超对方时可能成功 |

声望值影响：外交成功率、其他势力对你的态度、武将投奔意愿。

两种社交数值的区分：
- **关系值**：你和一个特定势力之间的双边关系（-100 到 +100），决定对方愿不愿意跟你结盟、通商
- **声望值**：你在整个天下的名望（0 到 1000），决定所有势力对你的基本态度，撕毁盟约和滥杀武将会降低声望

---

## 7. 间谍系统

| 间谍行为 | 效果 | 成功率取决于 |
|---|---|---|
| 刺探 | 显示目标城详细数值（兵力、钱粮、城防） | 智力差 |
| 离间 | 降低目标城中某武将忠诚度 | 智力+魅力 |
| 破坏 | 降低目标城防值或烧毁粮草 | 智力 |
| 谣言 | 降低目标城民心/治安 | 智力 |

派遣间谍需消耗金钱，行动可能失败并被发现（恶化外交关系）。

---

## 8. 战斗系统

### 8.1 进入战斗

两军在同一地块相遇 → 切到战场场景。战场根据发生地地形生成（平原开阔、山地有障碍、河边有水域）。

### 8.2 战场操控（实时）

- 俯视战场，拖拽框选己方部队
- 右键点击地面：移动
- 左键点击敌军：攻击
- 武将技能按钮：冷却完成后可释放

### 8.3 士气与经验

- **士气**：部队在战斗中的状态值（0-100），受武将武力、战况影响。每击杀一个敌方单位小幅提升，己方部队被击杀则下降。士气归零则部队溃散
- **经验**：部队的长期积累值，战后根据歼敌数提升。经验高的部队在战斗中有攻击和防御加成

### 8.4 胜负条件

- 一方部队被全灭
- 一方士气归零（自动溃散）
- 一方主动撤退（指挥官可以下令撤退，保留残部）

### 8.5 战斗结算

胜利方：占领城池 / 消灭野战部队；失败方：损兵折将，可能损员武将。战果传回主地图。

### 8.6 第一期范围

- 三种兵种
- 每个武将 1-2 个技能
- 三种地形
- 基础 AI 指挥（根据难度不同）

## 9. AI 系统

五个难度等级，AI 不作弊（数据不造假），靠决策水平区分：

| 难度 | 名称 | 决策特征 |
|---|---|---|
| 1 | 新手 | 被动防守，经营效率 60%，很少主动进攻 |
| 2 | 简单 | 正常经营，偶尔进攻相邻弱城，不使用外交 |
| 3 | 普通 | 经营合理，使用外交结盟，会趁玩家空虚偷袭 |
| 4 | 困难 | 经营最优，多线进攻，使用间谍离间，优先集火最强玩家 |
| 5 | 地狱 | 在困难基础上，AI 势力间也会结盟围堵玩家，战略眼光长远 |

AI 每回合执行的决策流程：
1. 评估自身实力（兵力、经济、武将）
2. 评估邻国威胁
3. 决定战略目标（扩张/防守/发展）
4. 具体行动（经营→外交→调兵→战斗）

---

## 10. 游戏流程

```
开始 → 主菜单（新游戏/读档/设置）
       ↓
    新游戏 → 选择势力 或 自建势力（输入名字、选择初始城池）
       ↓
    新手引导（逐步解锁功能按钮）
       ↓
    主游戏循环：
       经营阶段（回合制）
       ↕ 进入战斗则切实时战场
       ↓
    胜利条件：统一全图（占领所有城池）或 达到声望阈值
```

## 11. 存档系统

- **第一版**：浏览器 localStorage 存档（最多 5 个存档位）
- **后续**：账号系统 + 服务端云存档 + 联网对战

---

## 12. 不在第一期范围内的内容

- 联网对战（架构已预留）
- 水军和水战
- 历史事件剧情
- 复杂的武将养成（技能树等）
- 手机 App 打包
- 多语言
- 画面特效和复杂动画

---

## 13. 开发原则

- 逻辑层与画面层严格分离（便于测试和未来联网）
- 所有游戏配置数据（城池、武将、势力）放在 JSON 文件中，修改数值不需要改代码
- 每个系统独立开发、独立测试，完成后才组合
